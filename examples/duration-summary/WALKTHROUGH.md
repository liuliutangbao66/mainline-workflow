# 完整案例：CSV 耗时统计，从想法到返工验收

读完本页可以看到两个 Skill 分别做什么、用户需要说什么，以及交付错误时为什么不会直接记为完成。

**证据边界：前半段对话是教学编写的示例；后半段由 replay.py 实际调用工作流工具和统计脚本复现。不是独立 Agent 访谈记录，也不是多个真实会话的实验。**

## 1. 用户只提供项目内容

调用任务卡整理 Skill 后，用户可以直接写：

```text
$task-card-refiner
我有一份任务处理耗时CSV，想用Python统计平均耗时。
文件包含id和duration_ms，有些值缺失。希望本地运行，不安装第三方包，也不要改原始文件。
```

不用再附“请先提问、别重复问、最后生成任务卡”等流程引导。

## 2. 只补影响结果的问题

下面是建议的教学对话，不是模型运行日志：

**Agent：** 空值和无法解析的耗时是否应排除，并在结果中列出对应ID？建议排除，避免被当成0拉低平均值。

**用户：** 排除并记录ID。负数和非有限数也无效。

**Agent：** 输出采用JSON，包含有效行数、平均耗时和无效行ID，可以吗？没有有效行时平均值建议用null，避免误解为0。

**用户：** 可以。先用五行数据验证：10、20、空值、oops、30。有效3行、平均20毫秒，输入保持不变。

已有的本地运行、标准库、禁止修改输入等约束直接保留，不再询问。真实项目如果缺少文件位置，只补这个缺口；若路径已经提供，不必重复问。对于无法口头确定的性能或兼容性要求，应另列验证任务。

## 3. 一次复制给主线管家

采访结束后，任务卡整理会话交付一份类似 [完整启动任务卡](startup-card.md) 的材料。用户可以把整份内容复制给另一个会话。

主线阅读卡片、核对目录和授权，把A1–A3写入阶段验收。它只准备当前阶段的详细任务；不会为了“看起来完整”预先制造大量后续任务。这个案例的输入路径由复现脚本创建，因此无须猜测本机目录。

## 4. 第一轮能运行，但不应接受

演示脚本故意写入一个错误版本：把两条无效记录当作0参与平均值计算。

| 项目 | 第一轮实际结果 | 应有结果 |
|---|---|---|
| 有效行数 | 5 | 3 |
| 平均耗时 | 12毫秒 | 20毫秒 |
| 无效ID | r3、r4 | r3、r4 |

执行报告写的是“脚本运行结束，正确性待审查”。提交后状态只进入 pending_review。主线复算发现A1失败，登记rework，工具创建attempt-02。第一轮的脚本、结果、提交和审查文件保留。

演示还在第一轮待审查时使用handoff把负责人标签从guide-a变为guide-b，新标签读取brief后继续审查。**这是交接命令和记录的复现，不证明新模型会话必然能正确接手；没有创建新Agent。**

## 5. 第二轮修复，再接受

第二轮改为跳过无效行，实际输出：

```json
{"valid_count": 3, "mean_ms": 20.0, "invalid_ids": ["r3", "r4"]}
```

主线用Decimal单独读取原始CSV复算，核对A1、A2，并对比输入哈希核对A3。各项通过后，review绑定本轮candidate_id接受交付，再更新简短状态并运行check。

最后应看到：没有活动任务，最近接受T001，负责人guide-b；两轮证据都存在。check验证记录一致性，统计正确性来自复算记录，两者不能互相替代。

## 6. 亲自复现

在仓库根目录运行，输出目录必须不存在：

```text
python -B -X utf8 examples/duration-summary/replay.py --output demo-runs/first-run
```

运行不调用模型、不联网、不安装依赖；只在指定的新目录写文件并运行随案例提供的统计程序。再次使用相同输出路径会拒绝，换一个目录即可。

维护者本轮实际执行的 [结果快照](observed-result.json) 与 [命令返回记录](observed-commands.json) 随案例提供，便于先审阅再运行。

检查这些结果（相对于输出目录）：

| 文件 | 用途 |
|---|---|
| demo-result.json | 两轮数值、交接、输入/旧轮保留检查、最后状态 |
| demo-log/commands.json | 实际工具命令名称及返回值 |
| demo-log/resumed-brief.json | 交接后读到的必要入口 |
| .workflow/STATE.md | 当前简短结论及下一步 |
| .workflow/tasks/T001/attempt-01/ | 错误版本、报告及退回理由 |
| .workflow/tasks/T001/attempt-02/ | 修复版本、执行结果及逐项接受证据 |

如要验证复制后的安装包，可追加 `--skills-dir` 指向包含两个技能目录的父目录。默认直接读取本仓库skills/，无需先安装即可运行案例。

要检查真正的多轮访谈表现，需要另外让用户或独立Agent从原始想法开始试用，观察是否重复提问、遗漏约束或错误扩大授权。本案例没有覆盖这一项。
